=FINDINGS=
* [high] API compatível com S3 usando AWS Signature v4; endpoint por região no formato https://{region}.magaluobjects.com, com 2 regiões: br-se1 (Sudeste/SP) e br-ne1 (Nordeste/Fortaleza)
  Endpoints oficiais: https://br-se1.magaluobjects.com e https://br-ne1.magaluobjects.com (confirmado em docs.magalu.cloud/docs/storage/object-storage/additional-explanations/regions e no provider Magalu do rclone). Operações documentadas: criação/listagem/deleção de buckets, PutObject/GetObject/DeleteObject/HeadObject/ListObjects, cópia entre buckets, multipart upload (exemplo .NET com partes de 5 MB), versionamento, object lock, ACLs, bucket policy, CORS. URL pública de objeto: https://{region}.magaluobjects.com/{bucket}/{objeto}.
* [high] Presigned URLs suportadas apenas para métodos GET e PUT; presigned POST (form POST policy) não é documentado e deve ser considerado não suportado
  Doc oficial (how-to/objects/url-objects): 'Supported Methods: GET and PUT only'. Geração via mgc CLI (`mgc object-storage objects presign s3://BUCKET/OBJETO --expires-in 72h --method GET|PUT`), via AWS CLI (`aws s3 presign` / generate-presigned-url --expires-in em segundos) e via AWS SDK JS v3 (getSignedUrl de @aws-sdk/s3-request-presigner com PutObjectCommand — exemplo oficial na página de troubleshooting/presigned-url usando @aws-sdk/client-s3 3.677.0). Não é possível gerar presigned URL pelo Console. Nenhuma menção a limite máximo de expiração.
* [high] CORS é configurável por bucket, via Console (console.magalu.cloud) e via mgc CLI (`mgc object-storage buckets cors set|get|delete`); configuração via S3 API PutBucketCors não é documentada
  Página dedicada: docs.magalu.cloud/docs/storage/object-storage/access-control/bucket-cors. Campos suportados: AllowedOrigins, AllowedMethods, AllowedHeaders, ExposeHeaders, MaxAgeSeconds, em JSON. Comando: `mgc object-storage buckets cors set [bucket] --cors <arquivo-ou-JSON-inline>` (também get e delete). A doc NÃO cita aws s3api put-bucket-cors; funcionamento via API S3 direta não confirmado em fonte primária. CORS não substitui permissão: exige ACL ou Bucket Policy válida junto.
* [high] Autenticação por API Keys (par access key / secret) criadas em id.magalu.com/api-keys ou via `mgc object-storage api-key create`; funcionam como credenciais AWS em aws-cli, boto3 e AWS SDK JS v3 com endpoint customizado
  Criação no Console: ID Magalu > Criar API Key > nome, prazo de expiração, marcar Object Storage e escopo (leitura/escrita/ambos). Uso com AWS CLI: `aws configure` com access key/secret + `endpoint_url = https://br-se1.magaluobjects.com` e `region = br-se1` no ~/.aws/config. Exemplo oficial JS v3: new S3Client({ region: 'br-se1', endpoint: 'https://br-se1.magaluobjects.com', credentials: { accessKeyId, secretAccessKey } }) — o exemplo oficial JS NÃO usa forcePathStyle; o exemplo .NET exige ForcePathStyle = true, SignatureVersion 4 e UseChunkEncoding = false.
* [high] CLI própria existe: mgccli (github.com/MagaluCloud/mgccli), versão mais recente v0.62.0 (publicada 2026-07-17)
  Instalação: brew tap MagaluCloud/homebrew-mgccli && brew install mgccli (macOS); snap install mgccli; APT repo (sudo apt install mgccli); binários .deb/.rpm/.tar.gz/.zip nas releases do GitHub (Linux/macOS/Windows, AMD64 e ARM). Auth: `mgc auth login` (browser) ou --api-key. Comandos object-storage: buckets (create, delete, list, acl, cors, label, object-lock, policy, public-url, versioning) e objects (upload, upload-dir, download, download-all, list, delete, delete-all, copy, copy-all, move, move-dir, head, presign, public-url, sync, versions) + api-key (create/list). Região default da CLI: br-se1.
* [high] Preços (magalu.cloud/precos/object-storage, em BRL): Standard R$ 0,10/GiB-mês de armazenamento e R$ 0,10/GiB de egress; Cold Instant R$ 0,06/GiB-mês, egress R$ 0,20/GiB e ingress R$ 0,01/GiB
  Ingress Standard é gratuito. Não há preço por requisição listado na página de preços (cobrança documentada = armazenamento + tráfego). Sem free tier documentado. Modelo pay-as-you-go, medição mensal em GiB.
* [high] Limites do produto: objeto máximo de 5 TB; multipart com máximo de 10.000 partes; 100 buckets por conta; rate limit global de 3.000 requisições/segundo por tenant (HTTP 429 ao exceder)
  Fonte primária: docs.magalu.cloud/docs/storage/object-storage/additional-explanations/product-limits. Sem limite de número de objetos por bucket nem de tamanho total do bucket. Multipart recomendado para objetos > 8 MB; com chunk default de 5 MiB do rclone, arquivos de ~100 GB estouram as 10.000 partes — docs recomendam chunk > 10 MiB (testes oficiais com melhor desempenho: chunk 32 MiB, 16 transfers). Atenção: a página rclone-best-practices escreve o limite como '10Mi' (notação ambígua), mas a página product-limits confirma 10.000 partes.
* [high] Bucket público vs privado: bucket público habilita apenas listagem; acesso público a objetos individuais exige ACL public-read no objeto (ou bucket policy); mídia privada é servida via presigned GET com expiração
  Hierarquia de controle: Bucket Policy > ACL > público/privado. URL pública: `mgc object-storage objects public-url bucket/arquivo` ou formato direto https://{region}.magaluobjects.com/{bucket}/{objeto} (exige ACL prévia). Para upload público via presigned PUT, o cliente DEVE enviar o header x-amz-acl: public-read na requisição PUT (a ACL embutida só na URL assinada não é aplicada — página troubleshooting/presigned-url); PUT presigned exige os headers x-amz-acl e Host corretos na assinatura.
* [high] Limitações vs S3 real: sem lifecycle rules, sem event notifications, sem replicação; a API não implementa aws-chunked (Content-Encoding aws-chunked / streaming checksums), o que quebra SDKs AWS recentes
  Nenhuma página de docs.magalu.cloud documenta lifecycle/ciclo de vida, eventos ou replicação para Object Storage (buscas dedicadas não retornam nada; a CLI também não tem subcomando lifecycle) — considerar não suportados. Suportados: versioning (ativação via CLI/AWS CLI; rclone não baixa/deleta versões), object lock, ACL, bucket policy, CORS, storage class Cold Instant, sites estáticos via CDN externa (Cloudflare). Incompatibilidades documentadas por SDK: boto3 >= 1.36.* quebra (erro 'Credentials or specified url is malformed') — usar <= 1.35.99; AWS SDK PHP até 3.335.0; .NET exige UseChunkEncoding=false. Essas versões-teto coincidem exatamente com a mudança de jan/2025 dos SDKs AWS (default integrity protections com CRC32/aws-chunked), reforçando que o backend não aceita aws-chunked.
* [medium] Para AWS SDK JS v3 moderno (>= 3.729.0), uploads tendem a falhar com defaults novos de checksum; usar requestChecksumCalculation/responseChecksumValidation = 'WHEN_REQUIRED' ou fixar versão <= 3.7xx antiga (doc oficial usa 3.677.0)
  Inferência a partir do padrão: boto3 quebrou exatamente em 1.36.0 (release dos default integrity protections) e a Magalu manda fazer pin em 1.35.99; o equivalente no JS SDK é 3.729.0. A doc da Magalu não menciona explicitamente as flags WHEN_REQUIRED para JS — apenas fixa @aws-sdk/client-s3 e @aws-sdk/s3-request-presigner em 3.677.0 nos exemplos. Não confirmado em fonte primária se WHEN_REQUIRED sozinho resolve (o aws-chunked também é usado em uploads de stream com Content-Length desconhecido); teste necessário. Nota: presigned URLs geradas pelo s3-request-presigner não usam aws-chunked, então presigned PUT do browser é a rota mais segura.
* [medium] Presigned POST (createPresignedPost) não aparece em nenhuma doc da Magalu; suporte desconhecido/provavelmente ausente
  A doc de presigned URLs lista explicitamente apenas GET e PUT como métodos suportados. Não há qualquer menção a POST policy/form upload em docs.magalu.cloud. Para upload direto do browser, o caminho documentado é presigned PUT + CORS no bucket.
* [medium] Classes de armazenamento: Standard e Cold Instant (acesso imediato, mais barato para armazenar, egress mais caro e ingress pago)
  Cold Instant documentada em /docs/storage/object-storage/storage-classes/cold-storage/. Nome exato do valor de StorageClass a passar na API S3 (ex.: 'COLD_INSTANT'?) não confirmado nas páginas consultadas.
=GOTCHAS=
- A API S3 da Magalu NÃO implementa aws-chunked: SDKs AWS lançados a partir de jan/2025 (boto3 >=1.36, JS v3 >=3.729.0, PHP >3.335.0) enviam checksums CRC32 em streaming por default e quebram uploads — fazer pin de versão ou desativar checksums default (WHEN_REQUIRED); em .NET, UseChunkEncoding=false
- Em presigned PUT, a ACL passada na geração da URL NÃO é aplicada automaticamente: o cliente precisa reenviar o header x-amz-acl (ex.: public-read) na requisição PUT, e esse header entra na assinatura — esquecer o header no fetch/axios do browser dá SignatureDoesNotMatch ou objeto privado
- Rate limit global de 3.000 req/s por tenant (retorna 429) — relevante se servir mídia diretamente do bucket sem CDN
- Multipart: máximo 10.000 partes (não 10 milhões — a página rclone-best-practices usa a notação ambígua '10Mi'); com partes de 5 MiB o teto prático é ~48 GiB, aumentar chunk size para arquivos grandes (docs recomendam >10 MiB; teste oficial usa 32 MiB)
- Bucket 'público' só habilita LISTAGEM; cada objeto precisa de ACL public-read (ou bucket policy) para GET anônimo
- CORS por bucket só é configurável via Console ou mgc CLI segundo a doc; PutBucketCors via API S3 não é documentado — não assumir que aws s3api put-bucket-cors funciona sem testar
- Presigned POST (form POST) não é documentado; apenas GET e PUT — planejar upload de browser via presigned PUT + CORS
- Lifecycle rules, event notifications e replicação não existem na doc — limpeza de objetos órfãos precisa ser feita por job próprio (cron); sem webhook de upload concluído
- Máximo de 100 buckets por conta e objeto máximo de 5 TB
- rclone não suporta download/deleção de versões de objetos na Magalu; geração de public-url é exclusiva da mgc CLI
- Não há preço por requisição na página de preços (cobrança = armazenamento GiB/mês + tráfego), mas confirmar na fatura
- Egress do Cold Instant (R$0,20/GiB) custa o dobro do Standard (R$0,10/GiB) e ingress do Cold Instant é pago (R$0,01/GiB) — para mídia servida com frequência, Standard sai mais barato
=RECOMMENDATIONS=
- Para o app de flashcards (upload de mídia pelo browser): gerar presigned PUT no server (route handler Next.js) com @aws-sdk/client-s3 + @aws-sdk/s3-request-presigner, S3Client({ region: 'br-se1', endpoint: 'https://br-se1.magaluobjects.com', forcePathStyle: true, credentials }), e configurar CORS do bucket via `mgc object-storage buckets cors set <bucket> --cors cors.json` com AllowedOrigins do domínio do app, AllowedMethods ['GET','PUT'], AllowedHeaders ['*'], ExposeHeaders ['ETag']
- Servir mídia privada com presigned GET de curta expiração gerado on-demand no server (getSignedUrl com GetObjectCommand, expiresIn 300-3600s); presigned URLs não sofrem do problema aws-chunked
- Se usar @aws-sdk/client-s3 >=3.729.0, setar requestChecksumCalculation: 'WHEN_REQUIRED' e responseChecksumValidation: 'WHEN_REQUIRED' no S3Client e testar um PutObject server-side; se falhar, fazer pin em 3.677.0 (versão validada pela doc da Magalu)
- Criar a API key em https://id.magalu.com/api-keys com escopo Object Storage (leitura+escrita), guardar access key/secret em env vars; validar com aws-cli: endpoint_url no ~/.aws/config e `aws s3 ls`
- Instalar a mgc CLI no Ubuntu 24.04 via snap (`sudo snap install mgccli`) ou .deb das releases (v0.62.0) para administrar bucket, CORS, ACL e policies
- Implementar limpeza de uploads órfãos/incompletos via cron próprio (não há lifecycle rules); usar `mgc object-storage objects delete` ou DeleteObjects via SDK
- Manter o bucket privado e dar acesso só por presigned GET; evitar ACL public-read por objeto, exceto para assets realmente públicos
- Usar classe Standard para a mídia dos flashcards (egress mais barato e ingress grátis); Cold Instant só para backups
- Orçamento: R$0,10/GiB-mês + R$0,10/GiB egress (Standard) — para mídia muito acessada considerar CDN (ex.: Cloudflare) na frente, padrão documentado pela própria Magalu para sites estáticos

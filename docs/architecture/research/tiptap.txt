=FINDINGS=
* [high] A major atual do Tiptap é a v3 (não existe v4); latest estável no npm é 3.28.0, publicada em 2026-07-15
  dist-tags do registro npm em 2026-07-21: latest=3.28.0 para @tiptap/react, @tiptap/starter-kit, @tiptap/core e todas as extensões; v2-latest=2.27.2 (linha v2 em manutenção); nenhuma tag v4/next-4 existe. Tiptap 3.0 ficou estável em 2025 e a série 3.x segue como major atual.
* [high] React 19 é oficialmente suportado: peerDependencies de @tiptap/react 3.28.0 são react/react-dom '^17.0.0 || ^18.0.0 || ^19.0.0'
  Verificado direto no registry npm (versão 3.28.0). Também aceita @types/react ^19. Compatível com o stack do autor (React 19.2.4, Next 16.2.x).
* [high] SSR/App Router: componente do editor precisa de 'use client' + immediatelyRender: false no useEditor para evitar hydration mismatch
  Documentação oficial de instalação React (tiptap.dev/docs/editor/getting-started/install/react) instrui explicitamente usar a opção immediatelyRender para impedir render no servidor. v3 adicionou capacidade de rodar em ambiente SSR sem renderizar o conteúdo do editor. O editor em si é sempre client-side; para exibir conteúdo no server use o static renderer (ver abaixo).
* [high] LICENCIAMENTO: todas as extensões perguntadas são MIT/gratuitas na v3 — Image, FileHandler, Mathematics, CodeBlock, Placeholder, Underline, Highlight
  Mudança anunciada em 06/06/2025 (blog oficial 'We're open-sourcing more of Tiptap'): 10 extensões antes Pro viraram MIT: Details/DetailsContent/DetailsSummary, Emoji, DragHandle, FileHandler, InvisibleCharacters, Mathematics, TableOfContents, UniqueID. Confirmado no npm (2026-07-21): @tiptap/extension-file-handler 3.28.0 license MIT; @tiptap/extension-mathematics 3.28.0 MIT (peer: katex ^0.16.4 || ^0.17.0); @tiptap/extension-image, extension-placeholder, extension-underline, extension-highlight, extension-code-block-lowlight, extension-unique-id, extension-drag-handle-react — todos 3.28.0, MIT, não deprecados. O que permanece pago são os bundles cloud/serviço: Content AI, Collaboration (tempo real/Yjs hospedado), Conversion (import/export DOCX etc.), Documents, Comments, Snapshots/Versioning, Pages.
* [high] StarterKit v3 (MIT) já inclui CodeBlock, Underline e Link; Placeholder e Highlight ficam fora dele
  Docs oficiais do StarterKit v3: nodes Blockquote, BulletList, CodeBlock, Document, HardBreak, Heading, HorizontalRule, ListItem, OrderedList, Paragraph, Text; marks Bold, Code, Italic, Link (novo v3), Strike, Underline (novo v3); extensions Dropcursor, Gapcursor, Undo/Redo, ListKeymap, TrailingNode. Placeholder instala-se via @tiptap/extension-placeholder (ou via pacote agregador @tiptap/extensions, novo na v3); Highlight via @tiptap/extension-highlight. Ambos MIT.
* [high] Alternativa manual a FileHandler continua viável mas é desnecessária: editorProps.handlePaste/handleDrop (ProseMirror EditorProps) funcionam normalmente no Tiptap
  Como FileHandler agora é MIT, use-o (API com onPaste/onDrop e allowedMimeTypes). O fallback manual — editorProps: { handlePaste(view, event, slice), handleDrop(view, event, slice, moved) } lendo event.clipboardData/dataTransfer.files — é API estável do prosemirror-view (1.42.1 atual) e segue válido para controle fino (ex.: upload para storage próprio antes de inserir node image).
* [high] Mathematics MIT usa KaTeX como peer dependency; atenção: peer aceita katex ^0.16.4 || ^0.17.0, mas o latest do katex é 0.18.1 (2026-07-19)
  Instalar katex@0.17.x para satisfazer o peer range de @tiptap/extension-mathematics 3.28.0 (0.18.1 cai fora do range e gera warning/erro de peer no pnpm). Integração community com KaTeX não é mais necessária. Importar o CSS do katex manualmente.
* [high] Armazenar JSON (doc ProseMirror) e renderizar no server: o caminho recomendado na v3 é @tiptap/static-renderer (3.28.0, MIT) — renderToHTMLString, renderToReactElement, renderToMarkdown, sem DOM
  Função puramente JS: recebe JSON ou Node ProseMirror e devolve o formato alvo; ideal para RSC/rota estática no Next (renderToReactElement pode ser usado direto num Server Component). Alternativa clássica generateHTML de @tiptap/html ainda existe (3.28.0) mas na v3 tem peer dep em happy-dom ^20.8.9 para uso server-side — mais pesada. Sanitização: docs do static-renderer NÃO tratam de sanitização; o JSON validado contra o schema do editor já restringe estrutura, mas se o JSON puder vir adulterado do cliente, valide-o (TransformDoc/schema check ou zod) e/ou sanitize o HTML final (ex.: DOMPurify/isomorphic-dompurify ou sanitize-html) antes de servir — especialmente atributos de URL (href/src).
* [high] Node view React para cloze inline é padrão suportado: Node.create com inline: true, group: 'inline', atributos custom (clozeGroup, clozeId) + ReactNodeViewRenderer; NodeViewWrapper renderiza como <span> para nodes inline
  Docs oficiais de node views React (v3): ReactNodeViewRenderer conecta componente React ao node; NodeViewWrapper adapta a tag automaticamente (span para inline; customizável via prop as); atributos lidos via props.node.attrs e alterados via props.updateAttributes({...}); addAttributes() com parseHTML/renderHTML para persistir grupo/id no JSON. Para cloze com texto editável interno, usar NodeViewContent (content: 'inline*' ou 'text*'). Alternativa mais leve para cloze: Mark customizado com atributos + decorations (sem node view React), que preserva melhor o fluxo de texto; ambas viáveis. Caveat de performance: evitar trackNodeViewPosition (re-renders a cada mudança de posição); por padrão node views não re-renderizam por decoration/position — bom para muitos clozes por card. UniqueID (agora MIT) pode gerar ids automáticos.
* [medium] Mobile: problemas conhecidos reais — teclado virtual causa double-scroll e toolbar mal posicionada; iOS Safari perde seleção ao tocar botões de toolbar; BubbleMenu conflita com menu nativo de seleção do Android
  Issues no repo oficial: #6571 (jul/2025, aberto) — double scroll e toolbar flutuando no meio da tela com teclado aberto em iOS Safari/Android Chrome; #1806 — perda de seleção/focus em browsers mobile ao togglar marks (teclado sobe/desce; iOS Safari perde seleção — mitigação: onMouseDown preventDefault nos botões da toolbar); #55 — BubbleMenu vs magnifier/menu de seleção nativo do Android. Na v3, BubbleMenu/FloatingMenu migraram de tippy.js para Floating UI (import de @tiptap/react/menus) — há relatos de regressões de z-index/posicionamento (ex.: mantine #8415). Mitigações usuais: toolbar fixa posicionada com visualViewport API (interactive-widget/viewport-fit), evitar BubbleMenu em touch, botões com preventDefault em mousedown/touchstart para não perder foco do editor.
=GOTCHAS=
- katex latest (0.18.1) não satisfaz o peer range da @tiptap/extension-mathematics (^0.16.4 || ^0.17.0) — com pnpm isso vira erro/warning de peer; fixar katex@^0.17.0.
- Sem immediatelyRender: false o useEditor causa hydration mismatch no Next App Router; o editor sempre precisa de 'use client'.
- @tiptap/html (generateHTML) na v3 ganhou peer dep happy-dom para server — se o objetivo é só renderizar JSON no server, @tiptap/static-renderer é a via sem DOM e sem essa dependência.
- Tiptap descontinuou o 'free tier' da plataforma cloud, mas isso afeta apenas serviços hospedados (Collab/AI/Conversion/Documents); todo o editor + extensões citadas são MIT no npm — não confundir os avisos de pricing do site com o licenciamento dos pacotes.
- BubbleMenu/FloatingMenu na v3 mudaram de tippy.js para Floating UI e o import mudou (@tiptap/react/menus); código v2 de menus não migra 1:1 e há relatos de problemas de posicionamento/z-index.
- Static renderer não sanitiza nada (docs omitem segurança): se o JSON vem do cliente, valide contra o schema e sanitize href/src antes de renderizar.
- Docs oficiais mobile: issue #6571 (double scroll + toolbar deslocada com teclado virtual em iOS Safari/Android Chrome) seguia aberta em jul/2025 — planejar toolbar própria com visualViewport, não confiar em position:fixed puro.
- StarterKit v3 já traz Underline e Link — não instalar @tiptap/extension-underline/link separadamente para evitar duplicação de extensão (gera warning de nome duplicado).
=RECOMMENDATIONS=
- Adotar Tiptap 3.28.0 (fixar 3.x): @tiptap/react + @tiptap/pm + @tiptap/starter-kit cobrem CodeBlock/Underline/Link de graça; adicionar @tiptap/extension-placeholder, @tiptap/extension-highlight, @tiptap/extension-image, @tiptap/extension-file-handler, @tiptap/extension-mathematics + katex@0.17.x — tudo MIT, sem conta Tiptap Cloud.
- Componente do editor com 'use client' e useEditor({ immediatelyRender: false, ... }) para o App Router; nunca importar o editor em Server Component.
- Persistir o doc como JSON (jsonb no PostgreSQL) e renderizar o lado de revisão/leitura com @tiptap/static-renderer (renderToReactElement em RSC ou renderToHTMLString), passando a MESMA lista de extensões do editor; validar o JSON recebido do cliente e sanitizar URLs/HTML se houver qualquer vetor de conteúdo não confiável.
- Cloze: criar Node inline custom (inline: true, group: 'inline', content: 'text*', atributos clozeGroup/clozeId com data-attributes em renderHTML) + ReactNodeViewRenderer com NodeViewWrapper as='span'; usar @tiptap/extension-unique-id (agora MIT) para ids; no static-renderer, mapear o node cloze para o markup de oculta/revela na tela de revisão.
- Upload de imagem: FileHandler (MIT) com onPaste/onDrop fazendo upload para o storage e inserindo node image com URL final; manter editorProps.handlePaste/handleDrop apenas se precisar de controle além do que o FileHandler expõe.
- Mobile: usar toolbar fixa (não BubbleMenu) em telas touch, com onMouseDown={e=>e.preventDefault()} nos botões para não fechar o teclado/perder seleção no iOS; posicionar a toolbar com visualViewport API por causa do teclado virtual (issue #6571 ainda aberta); testar em iOS Safari real, não só emulador.
- Não contratar plano pago: os bundles pagos (Content AI, Collaboration, Conversion, Documents, Comments) são irrelevantes para flashcards single-user; colaboração futura pode usar Yjs self-hosted (y-websocket/hocuspocus OSS) sem o cloud da Tiptap.

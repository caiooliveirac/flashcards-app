* [high] Gotchas self-hosted confirmados na doc oficial: buffering do Nginx quebra streaming/SSE, cache ISR é por instância, Server Actions exigem chave de criptografia consistente entre builds/instâncias
  (1) Streaming/Suspense/SSE atrás de Nginx: enviar X-Accel-Buffering: no (via headers() no next.config ou na resposta do route handler SSE) senão o Nginx bufferiza; PPR também exige streaming fim-a-fim. (2) Cache ISR/dados fica em memória (50MB default) + disco local por instância; com PM2 em cluster mode cada worker tem cache em memória próprio — usar cacheHandler custom + cacheMaxMemorySize: 0 para consistência (disco é compartilhado entre workers na mesma máquina, memória não); revalidateTag() só invalida a instância que o executou (coordenar via refreshTags() em cacheHandlers se multi-instância). (3) Server Actions: chave de criptografia é gerada por build — definir NEXT_SERVER_ACTIONS_ENCRYPTION_KEY (base64, 32 bytes) para evitar 'Failed to find Server Action' em rolling deploys/multi-instância, e generateBuildId consistente + deploymentId para version skew. (4) middleware.ts foi renomeado para proxy.ts no Next 16 (middleware deprecated; proxy roda runtime Node.js, não edge) — afeta o padrão de middleware do Auth.js. (5) Atrás do Nginx, Auth.js exige AUTH_SECRET e AUTH_TRUST_HOST=true (confia no X-Forwarded-Host); AUTH_URL geralmente desnecessário no v5. (6) next/image funciona zero-config com next start (sharp embutido), mas Next 16 mudou defaults: minimumCacheTTL 60s->4h, qualities só [75], máx 3 redirects, IP local bloqueado por default.
* [high] Breaking changes do Next 16 relevantes para código novo
  Acesso síncrono a cookies()/headers()/params/searchParams totalmente removido (só async; helpers PageProps/LayoutProps via next typegen); revalidateTag() agora exige 2º argumento de cacheLife profile (novo updateTag() para read-your-writes em Server Actions, refresh() para router); PPR agora é via cacheComponents: true (flags experimental_ppr/dynamicIO/useCache removidas/deprecated); next lint removido (build não linta mais); AMP removido; serverRuntimeConfig/publicRuntimeConfig removidos (usar env vars + connection() para leitura em runtime); parallel routes exigem default.js explícito; next dev usa .next/dev separado do build.

=GOTCHAS=
- next-auth v5 nunca saiu de beta (beta.32 em 2026-07-20) e o projeto Auth.js está em modo manutenção sob o time do Better Auth — recomendação oficial para projetos novos é Better Auth; escolha next-auth v5 só por paridade com os projetos irmãos.
- Credentials provider não funciona com database sessions nem persiste usuários — com adapter Drizzle presente, forçar session strategy 'jwt' explicitamente ao usar Credentials + Google juntos.
- Atrás do Nginx o Auth.js exige AUTH_TRUST_HOST=true (senão callbacks OAuth quebram por host errado); AUTH_SECRET com >= 32 chars é obrigatório.
- Streaming/Suspense/SSE: Nginx bufferiza por default — enviar X-Accel-Buffering: no (headers() do next.config ou na resposta SSE) e/ou proxy_buffering off, senão loading.tsx e SSE chegam de uma vez só no fim.
- standalone NÃO copia public/ nem .next/static — esquecer o cp -r resulta em site sem CSS/JS/imagens; refazer a cópia a cada build no script de deploy.
- PM2 cluster mode = múltiplas instâncias Next: cache em memória divergente entre workers e 'Failed to find Server Action' após rebuild sem NEXT_SERVER_ACTIONS_ENCRYPTION_KEY/generateBuildId consistentes.
- revalidateTag() só invalida a instância local; no Next 16 passou a exigir segundo argumento (cacheLife profile) — para read-your-writes usar updateTag() em Server Action.
- Next 16: middleware.ts está deprecated e virou proxy.ts (runtime Node, sem edge) — tutoriais de Auth.js com 'export { auth as middleware }' precisam de adaptação.
- Next 16 removeu acesso síncrono a params/searchParams/cookies/headers — todo exemplo pré-16 com acesso direto quebra em runtime/type-check.
- next/image no Next 16 mudou defaults silenciosamente: minimumCacheTTL 4h, qualities travado em [75], máx 3 redirects, otimização de IP local bloqueada — pode surpreender com imagens 'não atualizando' ou quality prop ignorada.
- Turbopack é o bundler default de build no 16: qualquer config webpack custom faz next build FALHAR (usar --webpack para opt-out ou migrar para turbopack.*).
- shadcn/ui: docs/exemplos antigos assumem Radix, mas o default do CLI desde jul/2026 é Base UI — misturar bases sem perceber gera imports inconsistentes; escolher explicitamente no init.
- zod 4: usar @hookform/resolvers >= 5.2.2 (bugs de output type e discriminated unions no zod4 corrigidos só em 5.2.x); a tipagem de useForm mudou no resolvers 5.
- NEXT_PUBLIC_* é inlined no build — build standalone promovido entre ambientes precisa de connection() + env server-side para valores runtime (serverRuntimeConfig/publicRuntimeConfig foram removidos).
- Self-hosted não tem mitigação automática dos CVEs de RSC (CVE-2025-66478 CVSS 10.0) — manter 16.2.x atualizado; patches mensais agendados começam exatamente hoje, 2026-07-21.
=RECOMMENDATIONS=
- Stack base: next@16.2.10 + react@19.2.7 + react-dom@19.2.7 + TypeScript >= 5.1 (Node 22.23.1 do servidor atende o mínimo 20.9). Não usar 16.3.0-preview em produção.
- Deploy: output: 'standalone' no next.config, copiar public/ e .next/static para dentro de .next/standalone, PM2 rodando 'node .next/standalone/server.js' (PORT/HOSTNAME via env do ecosystem file). Se usar PM2 cluster mode, definir NEXT_SERVER_ACTIONS_ENCRYPTION_KEY e considerar cacheHandler custom com cacheMaxMemorySize: 0; em fork mode single-instance o default (disco local) funciona.
- Auth — decisão consciente: os próprios maintainers (time Better Auth) recomendam Better Auth para projetos novos; mas se o objetivo é manter paridade com os projetos irmãos do autor (next-auth v5 beta + drizzle), usar next-auth@5.0.0-beta.32 + @auth/drizzle-adapter@1.11.3 + drizzle-orm@0.45.2, sabendo que v5 tende a permanecer beta indefinidamente (recebe manutenção, publicou release ontem).
- Sessão: com Credentials + Google no mesmo app, usar adapter Drizzle para persistir users/accounts mas session: { strategy: 'jwt' } explícito (Credentials não funciona com database sessions); AUTH_SECRET obrigatório, AUTH_TRUST_HOST=true atrás do Nginx, provider Google via AUTH_GOOGLE_ID/AUTH_GOOGLE_SECRET.
- UI: tailwindcss@4.3.3 + shadcn CLI 4.13.1 ('npx shadcn create' ou init). Decidir a base de primitivos no init: Base UI é o novo default em jul/2026; usar '-b radix' se quiser ficar no Radix como os docs/tutoriais mais antigos. Componentes continuam copiados para o repo via registry, não são dependência.
- Forms: react-hook-form@7.82.0 (NÃO usar 8.0.0-beta) + @hookform/resolvers@5.4.0 + zod@4.4.3; adotar a tipagem nova useForm<Input, Context, Output> quando usar z.coerce/transform.
- Nginx: proxy_buffering off (ou responder X-Accel-Buffering: no) nas rotas de streaming/SSE; manter proxy_set_header X-Forwarded-Host/Proto para o Auth.js; usar proxy reverso na frente do next server (recomendação oficial).
- Código novo já no padrão Next 16: params/searchParams/cookies/headers sempre await; arquivo proxy.ts em vez de middleware.ts; revalidateTag(tag, profile) ou updateTag(); sem next lint (configurar ESLint flat config direto).
- Ops: assinar/monitorar os patches mensais do Next.js Security Release Program (começa 2026-07-21) — self-hosted precisa aplicar manualmente; nunca ficar em versão anterior a 16.2.x por causa do CVE-2025-66478 (RCE crítico RSC).
